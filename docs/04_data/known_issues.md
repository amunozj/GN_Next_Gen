## The KMAS single-use rule

KMAS appears **twice** in `data/raw`: as a reference survey in `reference_groups_2026-10/` and as an
observer-count source in `gn_observer_extension_2026-10/`. Its counts are derivable from its areas,
so using both puts the same observations into the likelihood twice and makes the posterior
overconfident.

> **Any run must declare KMAS's role as either reference areas or observer counts, never both.**

SWPC carries no such constraint: its areas are not in the reference. **Enforced in code since Step 1**, in two independent places, because documentation alone did not
prevent it: `gn_next_gen.config.validate_run_config` refuses a run that calibrates on KMAS in both
guises, and `gn_next_gen.io.load_observations` withholds KMAS counts whenever `kmas_role` is
`reference` — so a caller that bypasses the config still cannot double-count. The **default role is
`reference`** (PI, 2026-11-21), since KMAS is the only survey bridging the two ADR-009 anchors
through cycle 20. The rule also remains documented here, in both folder READMEs, and in the
extension's `role` column. See ADR-009.
